# 场景 & 人物站位一致性 研究 + 通用导演台工具设计

> 2026-08-24 · 基于 AI_Video 现役管线（H3 Ref2VA + Motion Context 链式接力 + 毛白技能包）与社区方案调研
> 目标：把"场景一致 + 角色站位一致"从 **prompt 文字玄学** 升级为 **结构化场景模型 + 自动化校验 + 参考层注入**。

---

## 一、现状盘点：已有的一致性机制

当前管线里其实已经有五层一致性手段，但**它们各自为政、没有打通**：

| 机制 | 位置 | 解决什么 | 现状局限 |
|---|---|---|---|
| ① Ref2VA 六段式 prompt | `skills/h3-ref2va-prompt` | 角色外观锁定（Subject + [Picture N] 绑定） | 只锁"长什么样"，不锁"站哪里" |
| ② 多参考图注入 | `build_prompt` → `ref_images` | 角色/场景/多角度外观锚定 | 参考图职责不分，layout 图从未进过参考层 |
| ③ Motion Context 链式接力 | `batch_r2v_chain.py` + `h3_r2v_motion_context_api.json` | 同 set 镜头间画面+音频 latent 续接 | 解决"时间上接得上"，不解决"空间上站得对" |
| ④ 毛白分镜构建器 Spatial Blocking Gate | `skills/毛白/分镜构建器` | 俯视调度图 + 轴线 + 距离/朝向 + 禁止项 | 只输出给"人看"的确认文本，没有结构化数据，也不进 manifest/参考层 |
| ⑤ 手动场景重复定义 | 每镜 prompt 的 Subject 2/3 | 场景外观重复声明 | 全凭手写，跨镜头无校验，易漂移 |

### 发现的实锤问题

**1. manifest 字段语义错位（会直接喂错参考图）**

`shots/_smoke_crane_v5_manifest.json` 实际内容：

```
set xiaole_crane_v5_cast1 (镜1 嘉玲开场):
  storyboard = ../characters/jialing_wizard/reference.png   ← 分镜位塞的是角色图
  character  = ../scenes/hogwarts_old_hall.png              ← 角色位塞的是场景图  ✗
  scene      = ../scenes/hogwarts_old_hall.png
set xiaole_crane_v5_cast2 (镜4/5 施咒变公鸡):
  storyboard = ../characters/xiaole_wizard/reference_new.png
  character  = ../scenes/hogwarts_old_hall.png              ← 又是场景图 ✗
  scene      = ../characters/rooster/reference.png          ← 场景位塞的是公鸡角色图 ✗
```

`batch_r2v_chain.py` 的 `build_prompt` 直接按 `storyboard→LoadImage(137)`、`character→LoadImage(139)` 对位填充，**字段填错 = 模型看到的参考图错位**。空间一致性在这种输入下无从谈起。

**2. 空间信息散落在自然语言里，无结构化模型**

- 镜1 "sits in the old antique swivel chair **in the center of the hall**"
- 镜4 "the paper crane **mid-air** transforms into a rooster"
- 镜5 "lands **right on top of** the boy's head"

每句都靠手写，模型每镜重新理解一次。**没有一个"场景地图 + 站位坐标 + 摄影机位"的权威数据**，因此：
- 无法自动检查"角色是否跨镜头跳位 / 朝向冲突 / 距离矛盾"
- 无法在多个 set 之间复用同一份空间事实
- 无法生成"带站位标注的俯视布局图"作为参考图喂给 H3

**3. 场景一致性靠文字重复，无资产锁定**

同一个礼堂，每个镜头把"stone walls, candles, amber stained glass"重写一遍。只要有一镜漏写或写偏，场景就开始漂移。缺一个"场景资产 = 场景参考图 + 空间 layout 板"的绑定。

## 二、社区调研：一致性的三大杠杆

调研来源：inVideo 官方 FAQ、Domer AI 导演指南、UD Blockchain 多镜头工作流、MiniMax H3 Ref2VA 官方指南、RunComfy H3 工作流、Leadde H3 实战博客。

### 杠杆 1：参考锚定（最有效，>95% 角色一致性）
> "身份进参考层，不进文字层。prompt 是 specification，不是 lock。"

- 每个镜头喂**同一组**角色参考图（正/侧/全身/特写 + 服装细节）
- 场景/环境用单独参考图锁定色调与空间关系
- 参考密度 ≤ 参考清晰度：**每张参考图一个职责**（身份 / 服装 / 场景 / 动作 / 运镜 / 声音）
- 一个角色 = master identity + wardrobe + environment **分开存**

### 杠杆 2：链式生成（空间/光照从上一段继承）
> "Open every sequence with a wide establishing shot, then each subsequent shot is generated with the previous clip attached as spatial layout reference."

- H3 Motion Context（latent 续接）与 Seedance R2V（尾帧 re-feed）同一思路
- 空间、光向、站位从上一段继承 → shot 5 仍 match shot 1
- 段长铁律 5–8 秒，超 10 秒尾帧糊/人物漂移

### 杠杆 3：关键帧锁定（先锁 blocking 再生成）
> "Layout the scene's key frames as a single vertical composite and animate from it."

- storyboard 关键帧图（垂直拼接）固定构图/站位/光影
- 每镜都以它作参考 → 所有镜头继承同一 setup
- 代价是牺牲意外镜头，适合连续性优先的场景

### 生产原则（可落地的纪律）
- **Locked vs Generative**：锁定已批准元素（身份/服装/场景/关键构图），只生成未决定元素（运镜/表演/氛围）
- **Source-of-Truth**：master 资产与生成产物分离；**不要**用上一段生成 clip 当唯一参考（错误会累积）
- **先锁后生成**：参考集未锁定不许出片；中途改一次资产，后续镜头自动继承
- **给每个参考图显式分配 job**（H3 官方也要求：identity / style / motion / camera / voice）

## 三、通用导演台工具设计

### 核心思路

把"空间一致性"从 prompt 文字 → **结构化场景模型（Scene Layout Graph）**，由工具统一生成、注入、校验：

```
                    ┌─────────────────────────────┐
                    │        导演台 Director       │
                    │   (Scene Layout Graph)       │
                    │  ├ 场景资产表                │
                    │  ├ 角色资产表                │
                    │  ├ 站位清单 Blocking Sheet   │
                    │  └ 镜头表 Shot Table         │
                    └──────────┬──────────────────┘
                    ┌──────────┴──────────────────┐
                    ▼                             ▼
        ① manifest 编译器                 ② 一致性校验器(lint)
        (每镜 prompt + ref_images 清单)     (字段语义/站位冲突/引用一致性)
                    │                             │
                    ▼                             ▼
        ③ 参考层注入(布局图/尾帧)  →  H3 Ref2VA + Motion Context 链式
```

### 数据模型（三个 Registry + 一张 Sheet）

```yaml
# 场景资产表 scene_registry.yaml
scenes:
  hogwarts_old_hall:
    plate: scenes/hogwarts_old_hall.png        # 场景参考图
    layout_plate: scenes/hogwarts_old_hall_layout.png  # 带站位网格的俯视图(可进 ref)
    axis_north: 高窗/祭坛    axis_south: 入口
    keywords: stone walls, amber glass, candles, long tables

# 角色资产表 character_registry.yaml
characters:
  jialing_wizard:
    identity: characters/jialing_wizard/reference.png
    wardrobe: ...            # 服装单独参考(可选)
    angles: [front, side, quarter]
    props: [wooden_wand]
  rooster:   { identity: characters/rooster/reference.png }

# 站位清单 blocking_sheet.yaml (每套 set 一份)
set: xiaole_crane_v5_cast1
scene: hogwarts_old_hall
blocking:                        # 每镜的角色位置/朝向/相对距离
  shot1:
    jialing_wizard: { anchor: center, face: camera, seated: true }
    crane_props:    { anchors: [ceiling_center] }
    camera:         { pos: C1_south, lens: 50mm, move: slow_push }
    rules:
      - 禁止: 转椅离开礼堂中心
      - 禁止: 纸鹤体积超过手掌
  shot4:
    xiaole_wizard:  { anchor: center_left, face: toward_crane }
    rooster:        { anchor: mid_air_above, appears_from: crane }
    crane_props:    { anchors: [mid_air_in_front] }
    camera:         { pos: C2, lens: 85mm }
    rules:
      - 禁止: 公鸡出现在小乐身后
      - 保持: 纸鹤→公鸡 变换发生在空中同一位置
```

### 工具链四个组件

**① 导演台编辑器（生成 blocking）**
- 从剧本/分镜 → 调毛白分镜构建器生成分镜 → 为每个含 ≥2 角色的 set 生成**俯视 blocking 图**（ASCII/HTML SVG，条件允许时用 ImageGen 出"带站位标注的场景俯视图"）
- 输出：`blocking_sheet.yaml` + `layout_plate.png`

**② manifest 编译器（自动生成每镜 prompt + ref 清单）**
- 输入：scene_registry + character_registry + blocking_sheet + 对白/运镜
- 输出：每镜完整 prompt（subject_definitions 自动拼、retention_analysis 自动拼、**`⚠️空间布局` 段自动生成**）+ `ref_images` 清单（角色图/场景图/**layout_plate**/上一镜尾帧）
- 消除手写场景重复：场景描述从 registry 一次性取，不再每镜重写

**③ 一致性校验器（lint，本轮最便宜的增量）**
- **字段语义**：character 字段必须指向角色资产、scene 必须指向场景资产、storyboard 指向分镜/角色
- **引用一致性**：ref_images 顺序 ↔ [Picture N] 标签 ↔ prompt 引用，三者核对
- **站位冲突**：同角色跨镜头 anchor 跳变、朝向冲突、规则违反（如"禁止公鸡在身后"被镜5违反）
- **场景漂移**：同一 scene 在不同 set 的 prompt 描述是否与 registry 关键词一致
- 输出：结构化问题清单，提交前强制过 lint

**④ 参考层注入（增强 build_prompt）**
- `layout_plate`（带站位俯视图）作为独立 ref_image 喂给 H3 → 模型直接"看见"空间关系，而非仅从文字推断
- 链式段的首帧额外追加上一段**尾帧**（Source-of-Truth 原则下：尾帧作布局参考，master 图仍是身份来源）
- 这正好用上 H3 9 张 ref_image 的余量（现在只用了 2-3 张）

## 四、落地路线图

| 优先级 | 内容 | 工作量 | 收益 |
|---|---|---|---|
| **P0** | manifest 字段语义修正 + 一致性 lint 脚本 | 半天 | 立刻止住"参考图喂错"，最便宜 |
| **P1** | blocking_sheet 数据模型 + layout_plate 资产 + prompt 自动注入 `⚠️空间布局` | 1-2 天 | 空间一致性从手写变结构化 |
| **P2** | layout_plate / 尾帧进 ref_images 参考层 | 0.5 天 | H3 直接"看"空间 |
| **P3** | 导演台 HTML 编辑器（可视化 blocking + 校验报告） | 2-3 天 | 编剧/导演可协作，不改代码 |

**建议先做 P0**：写一个 `tools/consistency_lint.py`，把现有 manifest 全部扫一遍——刚才已经发现 v5 manifest 有 4 处字段错位，跑一次就能全部暴露。

- 毛白分镜构建器的 Spatial Blocking Gate → 其"空间确认文本"应**结构化落地**为 blocking_sheet（而非只给人看）
